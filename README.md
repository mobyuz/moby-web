# Moby Web

A website for the Moby desktop companion robot, with a public demo and a signed-in web app backed by the Moby API.

## Getting started on Windows

Use Node.js 24.13.0 and npm 11.6.2. Run these commands in PowerShell.

```powershell
git clone https://github.com/mobyuz/moby-web.git
Set-Location moby-web
npm.cmd ci --ignore-scripts --no-audit --no-fund
npm.cmd run dev
```

Vite prints the local URL in the terminal. The production build goes to `dist/`.

```powershell
npm.cmd run build
npm.cmd run preview
```

## Web app

Open `/app/` from the landing page. Keep the Moby API running at
`http://127.0.0.1:8080` or set `MOBY_API_ORIGIN` in this repo’s `.env.local`.

| Screen | API features |
| --- | --- |
| Sign in | Registration, email verification, password reset, password sign-in, and Google sign-in on loopback |
| Account | Profile, data export, account deletion, installation registration and revocation, consent, and Google linking |
| Assistant | Authenticated SSE chat with cancellation and tab-local conversation history |
| Voice | WAV transcription and speech synthesis with playback and download |
| Usage | Remaining quotas and reset time |
| API status | Process health, database readiness, and live OpenAPI |

Use the full link or code from your email in the verification and reset forms.
Registration uses `VITE_MOBY_TERMS_VERSION` and
`VITE_MOBY_PRIVACY_POLICY_VERSION`, which default to the API’s development
versions. Set them to match the policies accepted by your API instance.
Session credentials stay in memory and rotate through the API. Reloading
the tab requires signing in again.

Google sign-in is visible on both the sign-in and registration screens.
On `http://localhost:<port>`, choosing it opens the same app at `127.0.0.1`
before authentication. The API’s Google flow returns to
`http://127.0.0.1:<port>/oauth/moby`, so both tabs must use that origin for
the one-time code handoff. Only the signed-out entry point changes origins;
account linking and deletion keep their current in-memory session.

The API must be configured with `MOBY_GOOGLE_CLIENT_ID`,
`MOBY_GOOGLE_CLIENT_SECRET`, and `MOBY_GOOGLE_REDIRECT_URI`. These settings
belong to the API process, never to `VITE_*` or the website bundle. Without
them, the API returns 503 and the website offers email sign-in instead.
The current API accepts only a local loopback app callback, so a hosted
website callback needs separate backend support.
Desktop tools still run in the Moby desktop app. The web assistant uses text
turns and sends an empty tool catalog.

## Guest demo setup

Run the B6 API with `MOBY_DEMO_ENABLED=true`, the website hostname in
`MOBY_DEMO_HOSTNAME`, and the widget’s secret in `MOBY_TURNSTILE_SECRET_KEY`.
Copy `.env.example` to `.env.local` in this repository and set these values.

| Setting | Value |
| --- | --- |
| `MOBY_API_ORIGIN` | Upstream origin for Vite dev and preview, defaulting to `http://127.0.0.1:8080` |
| `VITE_MOBY_TURNSTILE_SITE_KEY` | Public site key for the Turnstile widget registered for the website hostname |

Restart Vite after editing `.env.local`. For a production build, set the
public site key before running `npm run build`. Visit the website using the
hostname configured in the API. With no site key, the website shows the demo as offline.
[API setup](https://github.com/mobyuz/moby-api#mehmonlar-uchun-veb-demo-api)

The widget uses the `demo_chat` action. Cloudflare’s dummy verification
response reports `test` as its action, while B6 checks for `demo_chat`.
Use a registered widget to verify against a live B6 instance.
[Turnstile testing](https://developers.cloudflare.com/turnstile/troubleshooting/testing/#validation-response)

In production, route `/v1/*`, `/health`, `/ready`, and `/openapi.json` on the
website origin to the API before serving static files. Serve `/app/` from
`dist/app/index.html`. Leave API responses uncached, stream assistant
responses without buffering, and allow the WAV request size specified by
the backend. If you use a Content Security Policy, allow the Turnstile script and frame from
`https://challenges.cloudflare.com`. The API uses the connection peer for its
rate limit, so visitors behind one upstream proxy share that peer’s limit.
[Turnstile CSP requirements](https://developers.cloudflare.com/turnstile/reference/content-security-policy/)

The website displays the API reply as plain text. The current B6 mock returns
a fixed reply in Uzbek. [API contract provenance](contracts/README.md)

## Verification

```powershell
npm.cmd run api:check
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
npx.cmd --no-install playwright install chromium
npm.cmd test
```

Playwright runs Vite with API fixtures and a stubbed Turnstile widget. It checks
guest requests, concurrent refresh, assistant streaming, and the Google loopback handoff.
To use an existing Chrome installation, set `$env:PLAYWRIGHT_CHANNEL = 'chrome'`
in PowerShell and run `npm.cmd test`.
